# PR 55 and Signaling Server PR 6 Review

Reviewed upstream heads: MCTier `e188846` and MCTier-Signaling-Server `db1db40`.
Decision: integrate both refactors with the corrections below.

## Findings and Corrections

- Client: `acceptControl` added an asynchronous native authorization step without
  checking whether the session still existed afterward. Stopping or leaving
  while authorization was pending could send a stale acceptance. The completion
  now checks the session and capture stream and revokes the stale grant. A test
  holds the native authorization promise, stops control, then resolves it.
- Server: a full password-failure table rejected every untracked source/lobby,
  including correct passwords and new passwordless lobbies. A regression test
  failed on the PR and passed after the fix. Capacity now evicts the least
  recently failed key; each key's queue is independently bounded. Existing
  lockout, expiry, source isolation, and wrong-password disconnect rules remain.
- The extracted client signaling module also contained two comparisons rejected
  by the local ESLint policy. Explicit null/undefined checks preserve behavior.

## Integration

The local 3.4.0 lobby encryption and cross-platform chat work was first preserved
in commit `4cf4c6a`. It was then merged with the reviewed client branch. The sole
content conflict was the deleted command monolith. All 208 top-level Rust items
were assigned to the new domain modules using a Rust parser. A separate token
comparison verified all 190 non-import items against the preserved local file,
allowing only visibility, module paths, formatting, and removal of an unused mut.

The command facade and wire protocol remain compatible with their pre-refactor
versions. This does not change the existing requirement to update both clients
for the local encrypted-chat feature. The server's loopback-only Compose port
requires the reverse proxy setup documented in its README.
