# 自动大厅虚拟 IP 冲突修复

## 原因

桌面端自动入厅固定调用创建流程；该流程把默认网络配置改成静态
`10.126.126.1/24`。已有成员占用 `.1` 时，即使密码正确也会注册失败。
Android 原先把设备标识散列到 240 个地址，发生碰撞后没有恢复路径；同时
没有解析注册错误的 `message` 字段，连接 WebSocket 后就提前显示已入厅。

## 当前行为

- 桌面端自动大厅走加入流程。创建和加入均采用同一地址策略，因此第一个
  成员进入空大厅也不需要等待其他 EasyTier 节点提供地址。
- 桌面默认配置和 Android 使用身份指纹、大厅名的 SHA-256 派生候选地址。
  首选地址避开旧客户端常用的 `.1`；后续候选覆盖 `.1` 至 `.254`，不重复。
- 地址散列不代表地址唯一。信令服务器仍是占用判定依据：收到确切的 IP
  冲突拒绝后，先停止旧网络及附属服务，再使用下一个地址和新的签名注册。
  初次连接和断线重连均可恢复，空密码大厅同样适用。
- 密码错误、其他注册拒绝和用户取消不会触发换址。扫描次数和恢复时间受限；
  桌面手动 IPv4 配置不会被静默改写，冲突时提示清空手动 IPv4。
- Android 等待注册成功后才进入大厅，失败或取消后清理 VPN、聊天、文件与媒体
  服务；启动和清理使用同一互斥锁，避免旧清理任务拆掉新会话。
- 保留现有信令协议和服务端 IP 唯一性校验。信令服务器改动仅为集成测试，
  无需为本次修复升级服务端协议。

## 验证

- JavaScript：自动大厅选择加入、保留加密密码/空密码、手动操作优先；初次
  注册和重连冲突清理顺序；换址范围、时间限制、取消与密码错误分流。
- Rust：地址候选覆盖、与 Android 一致的测试向量、配置继承与手动地址保护。
- Android JUnit：相同地址算法、冲突重试、时间限制、取消；真实 SignalingClient
  配合模拟 WebSocket 验证等待注册、拒绝原因保留、旧连接回调隔离。
- 信令服务器实际本地 WebSocket 集成测试：有密码及无密码大厅中，两个不同
  身份先使用被占用地址，被拒后换址成功；原房主不被替换，成员地址不重复。
- 桌面 TypeScript/Vite 构建和 Android 主程序/单元测试 Kotlin 编译。

本次最终结果：JavaScript 214 项、Android JUnit 53 项、桌面 Rust 大厅相关
50 项、信令服务器 68 项全部通过；`npm run build` 与 `cargo check --lib` 通过。
Android 的 `testDebugUnitTest` 使用仓库现有的 `jvmSecurityHardeningTest`
运行 JUnit，不能将外层任务显示的 SKIPPED 误解为未运行测试。

本次验证不包括两台物理设备上的 VPN/TUN、实际局域网游戏或公网中继端到端验收。
浏览器 CLI 未能启动，未将组件流程测试标记为浏览器界面验收。地址池耗尽、
用户手动指定重复地址、网络不可达仍会明确失败，不能保证任意环境永不报错。
