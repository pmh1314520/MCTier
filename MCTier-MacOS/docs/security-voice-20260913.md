# 密码保护、加密聊天与语音消息验证

## 已实现

- 电脑端最近大厅、收藏大厅保留 AES-256-GCM 加密的密码。密钥放在系统凭据库，不随 localStorage 一起保存。安卓沿用 Android Keystore 的 AES-256-GCM 加密大厅记录。
- 自动大厅密码使用系统凭据库；旧配置、导入配置中的密码先加密再替换，凭据库不可用时保留旧记录供重试。安卓加密失败不再删除最后一次保存的凭据。
- 自动填写的密码输入框只渲染固定占位值，没有明文显示按钮。手动编辑会替换保存的密码。
- 双端分享文本、二维码采用 v3 加密密码信封，分享海报不再单独绘制密码。兼容读取旧邀请，新邀请只生成 v3。
- 聊天请求与历史响应使用成员之间的 P-256 ECDH、HKDF-SHA256、AES-256-GCM。消息签名覆盖密文，请求继续验证信令成员、公钥、目标地址、时间戳及防重放随机数。私聊只发给指定成员，接收端拒绝错投。
- 文本、图片、语音及经过聊天接口的协作数据均使用同一加密通道。聊天历史和语音录制只保存在内存，不新增明文磁盘历史或临时录音文件。
- 双端强制 EasyTier AES-256-GCM；信令地址只接受 WSS。WebRTC 音视频继续使用浏览器/系统实现的 DTLS-SRTP。
- 双端大厅及私聊支持长按空输入框录音，包含计时、动画、上滑取消、取消按钮和最长 60 秒限制。切换会话或离开页面取消录音。安卓进入后台暂停语音消息播放。
- 电脑端全局与大厅配置支持 NVIDIA Broadcast/RTX Voice 输入设备自动选择；未检测到设备时关闭，保留普通麦克风的系统降噪。

## “已经在大厅中”修复

源码中的该错误来自 LobbyManager 的本地状态检查，截图本身不能证明服务器存在残留会话。

移除了重复的自动大厅启动事件入口；自动创建、手动创建、邀请加入之间增加取消和重复提交控制。后端在同一个锁内占用连接状态，拒绝重叠创建/加入；网络或 P2P 初始化失败清理半成品状态。重复请求不会再强制拆除已有大厅。

普通设置保存不再写入缓存的自动大厅开关，只有明确修改该开关才更新配置。仅凭用户截图无法确认其机器上的唯一触发链，仍需真实的“改子网代理、保存、重启”复测。

## 兼容性与尚未覆盖的边界

- 本版聊天拒绝旧的明文消息格式；参与聊天的双端必须一起更新。旧客户端不能解析新 v3 邀请。私有信令服务器必须配置有效 WSS。
- 可携带的邀请包含解密所需材料，是可转发的入场凭据。AES 防止分享文本直接显示密码，不阻止持码人通过程序解码。若要求接收者永远得不到密码，需要服务器签发可撤销的入场令牌和 EasyTier 授权协议改造。
- 固定占位值防止从密码输入框 DOM 读取明文；当前信令注册仍需要进程内密码，不能阻止设备所有者读取进程内存、修改客户端或调试系统凭据访问。
- 本地保护当前覆盖大厅密码及安卓大厅记录，尚未把所有配置、头像、最近玩家、统计、协作待办、历史日志和用户主动导出的文件统一迁移到加密存储。因此不能宣称“所有敏感数据存储已完成加密”。用户选择下载/导出的文件保持可用文件格式。
- NVIDIA 当前依赖已安装的 Broadcast/RTX Voice 虚拟麦克风，不是直接调用独立 RTX Audio SDK。仅检测到 NVIDIA 显卡不足以启用该功能，也尚未验证实际降噪效果。
- 旧设备密钥丢失后无法恢复对应的本地密文。复制本地配置到另一设备不能替代分享邀请。聊天密钥依赖受信任的信令成员公钥分发，当前没有实现前向保密棘轮。

这些改动尚未发布，也不应作为“全部安全需求均完成”或“绝对防破解”的发布声明。
