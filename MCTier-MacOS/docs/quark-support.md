# 夸克自动转存与支持记录

Windows 桌面端和 Android 端统一使用分享：
https://pan.quark.cn/s/aee110172d26

## 自动执行

- 用户通过扫码或手机号验证码登录成功后立即自动检查当日转存；无需点击转存按钮或再次开启开关。
- 已登录账号在应用启动时自动检查。旧版手动模式的登录会话同样生效。
- Windows 登录成功后自动注册当前用户的静默计划任务：每天北京时间 00:05 执行一次，登录 Windows 时补查，错过计划时间后允许补执行。不依赖主程序或赞助窗口，也没有常驻后台进程。
- Windows 任务检查完就退出。当日已有提交记录时只读取本机状态，不访问网络；提交前失败通过任务计划程序每 15 分钟重试，最多 96 次。主程序自身保留每 15 分钟的兜底检查。
- Android 登录后注册唯一 WorkManager 周期任务，每 12 小时由系统安排有网络条件的检查；应用进程协程每 15 分钟兜底检查一次，不依赖赞助窗口。
- Android 返回前台也立即检查。普通进程终止后由 WorkManager 恢复调度，覆盖升级广播恢复已有账号的任务；执行可能受省电与系统后台限制延后。被系统“强行停止”后需先手动打开应用，不补转存停用期间的历史日期。
- 本设备、当前账号当天已有提交或成功记录则跳过；跨日自动执行新一天的转存。
- 准备分享文件期间若跨日，放弃本次准备，下一轮按新日期执行，避免用昨天的记录提交今天的转存。
- 未登录不提交；退出登录立即请求停止，保留按账号隔离的历史记录。退出无法撤销已提交的云端任务。
- 登录失效或夸克要求验证时需要用户重新登录/完成官方验证。普通网络故障不会清空登录凭据。

转存会保存分享内容到用户网盘根目录，不下载到本机，也不打开浏览器。

## 重复提交和故障恢复

- Windows 主程序和独立计划任务共用同一份加密文件、同一个系统凭据库密钥与 OS 文件锁，每次操作先在锁内重读磁盘；后台确认成功的日期、累计次数和金额直接显示在主程序。Android 进程内的检查共用同一互斥锁。
- 获取分享内容失败、提交前断网或持久化失败，不消耗当日提交记录，下一次检查自动重试。
- 真正发送转存 POST 前先持久化当日记录；持久化失败则不提交，并回滚内存记录。
- 已发出转存请求但响应丢失、任务状态暂未确认时，当天不自动重复提交，以免生成重复文件。HTTP 客户端同样禁用写请求重试。
- 只有夸克任务明确完成才计入成功天数和参考金额；尝试记录不等于成功记录。
- 重启及退出后重登原账号保留当天提交记录。不同设备不共享记录。

## 界面

- Windows 主界面爱心入口、Android 赞助按钮均打开独立赞助窗口。
- 登录区域默认扫码，也可切换手机号；登录按钮可直接点击，不再要求勾选复选框。凭据本机加密保存，可随时退出。界面不再展示后台自启和关闭应用后继续运行的技术说明。
- 已登录区域展示「每日自动转存已开启，无需手动操作」，移除手动确认转存按钮。
- 不展示「MCTier Windows 安装包」容器。
- 收益参考仅展示手机 ¥0.47、电脑 ¥0.22 两行渠道费率，无起始日期和「仅有效推广渠道核算，非承诺收益。」文字。
- 首次/最近成功日期属于用户支持记录，不是收益参考的起始日期。
- 双端未登录用户每次启动界面时显示一次「免费持续支持 MCTier」邀请，灰色「下次一定」关闭，绿色「支持一下」打开原夸克赞助窗口。已登录不显示；本次跳过不会永久屏蔽下次启动。

- 邀请改为用户提供的四段赞助文案，说明免费支持、夸克承担费用、本地凭据和随时退出；Android 将「电脑本地」对应改为「手机本地」。手机号登录容器双端由 370 缩至 240，保留官方表单和验证流程。
- 早期界面调整曾通过 25 项原生测试、10 项前端测试、75 项 Android JVM 测试、前端生产构建和 Android Kotlin 编译。当时的真实 WebView2 检查覆盖本地状态就绪后立即弹出、更新优先、按钮无勾选门槛、240 高度表单、跳过/重新启动和已登录不弹出。Android 未进行真机视觉验收；本轮未重新打包发布安装包。

## Windows 静默任务与资源边界

- 任务名为 `MCTier-QuarkDaily-<当前用户 SID>`，只以当前已登录 Windows 用户身份运行（InteractiveToken、非提权），因此与主程序访问同一用户的凭据库。不保存 Windows 密码，不以 SYSTEM 运行。
- 动作为当前安装路径的 `mctier.exe --quark-background`。入口在 Tauri、单实例插件、GPU/音频、联机内核、WebView 与托盘初始化之前分流；不会激活现有主窗口或显示启动赞助邀请。程序使用 Windows GUI 子系统，注册/删除任务直接调用原生 Task Scheduler COM 接口，不启动 PowerShell、cmd 或其他脚本宿主。
- 工作进程使用单线程异步运行时、最低任务 CPU 优先级和 Windows 后台处理模式（降低 I/O、内存优先级），单次最多运行 150 秒。空闲时 MCTier 后台工作进程数为 0；不轮询注册表、不每分钟唤起进程，任务配置仅在登录、启动、退出及配置失败重试时进行。
- 电池供电允许运行，不主动唤醒睡眠电脑。不保证关机、休眠、退出 Windows 登录时执行；恢复并满足用户登录条件后补查当天，不补转存历史日期。网络断开、系统策略禁止任务、凭据库异常或夸克登录失效也无法保证成功。
- 扫码和短信完成登录后都注册；已有登录会话在下次启动新版主程序时自动补注册。移动便携版路径后须启动一次新版程序更新任务路径。任务注册失败显示独立错误并每 15 分钟重试，不冒充后台已启用。
- 退出夸克登录先写入跨进程停止标记，再在同一文件锁下清除 Cookie、保留历史并删除任务；即使此时主程序被终止，下次后台运行也完成凭据清理。已提交的云端任务无法撤回。NSIS 卸载钩子停止并删除指向该安装目录的任务。
- Windows 由任务计划程序唤起独立工作进程；Android 由 WorkManager 调度应用进程内的 Worker，两端均共享各自本设备的加密凭据和统计。Android 调度不保证准点运行。

## 统计与凭据

- 成功日期按账号和北京时间保存，重复日期幂等。每条记录保留当时费率快照，未来改价不重算历史。
- Windows 展示 PC 参考金额区间，Android 展示移动参考区间并保留 PC 口径说明；实际渠道和结算由夸克核定。
- Windows：应用数据目录 `quark-support.bin`，AES-256-GCM 加密，密钥在系统凭据库。
- Android：私有 `noBackupFilesDir/quark-support.bin`，AES-GCM 加密，AndroidKeyStore 密钥。
- 登录凭据仅用于直连夸克，不经过 MCTier 服务器，不通过桌面 IPC 返回，也不写入日志。
- Cookie 保留域名、路径和绝对有效期；二维码有效期 120 秒，过期自动刷新，关闭扫码窗口取消二维码轮询。

## 手机号 + 验证码登录（2026-10-01）

双端赞助窗口默认选中扫码登录，可切换到手机号登录。点击「开始手机号登录」后，直接在应用内输入手机号、获取短信并提交验证码；无需勾选前置复选框，也不需要安装夸克 App。切换方式、关闭窗口或重新打开登录表单会取消旧的本地登录会话，旧页回调不能完成新的登录。

### 官网流程证据

本次直接读取了夸克官网及其引用的公开页面/脚本，没有向真实号码发送短信：

- 官网：https://pan.quark.cn/
- 官网入口脚本：https://g.alicdn.com/quark-cloud-drive/quark-cloud-drive-static-page/0.1.78/js/index.js
- 手机号表单：https://uop.quark.cn/cas/custom/login?custom_login_type=mobile&client_id=532&display=pc
- 短信与提交逻辑：https://image.uc.cn/s/uae/g/82/sso/public/js/next/custom/mobilelogin_532_5079337.js
- 验证组件：https://image.uc.cn/s/uae/g/82/sso/public/js/next/aliyunCaptchaV2_8063713.js

观察到的接口链路：

1. 官方表单加载 AliyunCaptchaV2。默认 scene_v2 为 `1ml1ondj`，服务端要求滑块时切换 `y9x7vx0s`，获取 `captcha_data`。
2. 表单向 `POST https://uop.quark.cn/cas/custom/login/sendSmsCode?custom_login_type=mobile` 提交表单编码数据，包含 `display=pc`、`client_id=532`、`login_name`、`captcha_data`、`scene_v2`，以及官方维护的其他验证码字段。成功状态为 `2000000`，官网启用 60 秒重发倒计时。
3. 用户填写四位短信码后，表单向 `POST https://uop.quark.cn/cas/custom/login/commit?custom_login_type=mobile` 提交 `login_name`、`sms_code` 及表单隐藏字段。成功状态为 `20000`，响应 `data` 为 32 字符服务票据。
4. 默认 `transmission_mode=pm`：官方表单通过 `window.parent.postMessage` 交付票据。官网父页面同样内嵌此表单，并将票据作为 `st` 参数调用 `GET https://pan.quark.cn/account/info`，建立网盘会话。

### 双端实现

两端内嵌官方手机号表单，由官网维护短信请求、验证码倒计时和交互验证。未复制或绕过验证码生成逻辑。手机号和短信码由用户直接输入夸克页面，MCTier 原生服务只接收一次性服务票据，再向网盘账号接口交换会话。

- Windows：沙箱 iframe，仅允许脚本、表单和自身来源；父页面严格校验消息来源等于 `https://uop.quark.cn`，且发送窗口必须是当前登录 iframe。CSP 仅新增此域名的 frame-src，无远程 Tauri 权限。
- Android：专用 WebView 加载本地包装页，再内嵌同一官方表单。包装页校验官方来源和当前 iframe，使用仅交付给本地顶层页面的 WebMessagePort 传回票据。无 `addJavascriptInterface`，禁止文件/内容访问、混合内容及顶层外部跳转；销毁时关闭消息端口。
- 原生服务校验当前登录方式、会话 ID、10 分钟有效期及票据格式；二维码查询不会处理手机号会话。
- 验证账号、加密保存 Cookie 成功后，复用扫码登录的完成流程，立即安排当日自动转存。
- 票据只用于账号交换，不保存到本机记录、不在状态接口回传；不存储手机号、短信码。

验证：9 项前端/消息桥接测试、18 项 Windows 原生夸克测试、75 项 Android JVM 测试通过，双端类型/编译检查通过。Tabbit 路由不可用，未完成真实浏览器视觉验收；真实手机号短信、交互验证码及真机 WebView 登录仍需账号验收。本次未重新打包 EXE/APK。
