# 禁言、房主交接与原生麦克风试音修复

## 原因与修改

- 桌面 WebRTCClient 的 `player-mute-changed` 校验使用 `isKnownPlayer(id, false)`，排除了本机 ID；手机房主发出的正常禁言广播到达桌面后被丢弃。现在接受已知本机目标，并同步停止采集、移除发送音轨、关闭 UI 麦克风状态。禁言期间的开麦入口也拒绝启动，不依赖某个 React 面板是否挂载。
- Windows Store、Android 大厅状态及信令服务器在转交房主后都保留了旧禁言记录。现在主动转交及房主退出后自动接任都会清除新房主记录。客户端额外过滤旧服务器发来的房主禁言快照或通知，服务器拒绝禁言当前房主，并向旧客户端广播解除禁言。解除限制不会自动开启麦克风。
- 桌面试音原先经过第二个 AudioContext、8 位时域采样及线性缩放，无法可靠区分弱声和零电平。Windows 现在从 Rust/WASAPI 送来的 48 kHz 浮点 PCM 直接计算 RMS，不为试音另建分析音频图；显示采用 -60 至 0 dBFS，停止时归零。其它桌面平台使用浮点分析器和静音输出连接。此前现场日志证明采集引擎已运行，但没有记录实际试音 PCM 电平，不能仅凭日志认定上述旧测量路径是唯一因素。
- Android 注册或重连收到禁言快照时也会关麦；禁言通知不再依赖可能尚未同步的 UI micEnabled 值。

## 验证

- 前端原有及新增协议、原生电平回归：273 项通过；另有 2 项实际 Zustand Store 回归通过，覆盖接任、卸任、旧快照和不自动开麦。
- Android JVM 测试：65 项通过，含新加入 JUnit 运行列表的 LobbyModerationTest；Debug APK 编译成功。
- 信令服务器：69 项测试通过。真实 WebSocket 测试验证主动转交和房主断开、显式解除禁言广播、拒绝禁言房主及新成员快照。
- 真实 WebView2 测试使用合成语音走生产 Rust IPC / AudioWorklet 桥接、生产 WebRTCClient 与真实音轨：禁言后 sender 已移除、原生采集停止，接收声音能量不再增长到语音水平；接任后不自动开麦，手动开启后声音恢复。
- 试音测试同样使用真实 WebView2：浮点 PCM 的试音显示 62%，停止后为 0；原双向语音回归通过。

这些是本机和自动化验证，未代替用户电脑与 Android 手机的双机、真实麦克风测试。线上信令服务器未部署；新客户端兼容旧服务器的房主禁言记录，但服务器权威状态修复和旧客户端的完整同步需要更新节点服务。

## 现场复测

更新双端后分别测试：手机房主禁言正在说话的电脑玩家；电脑房主禁言手机玩家；将房主转交给被禁言者；被禁言者在原房主退出后自动接任；重新开麦和弱声试音。禁言应立即停止发声；接任后可手动开麦，不能自动打开麦克风。
